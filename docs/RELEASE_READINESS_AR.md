# بوابات إطلاق كلمات ماسنجر

هذه القائمة هي معيار الإطلاق، وليست ادعاءً بأن جميع البنود قد اجتازت الاختبار. لا يُعلن التطبيق جاهزاً للجمهور قبل إغلاق البنود الحرجة أدناه.

## الحالة الحالية بحسب المستودع

- [x] تطبيق ويب عربي RTL وواجهة قابلة للتثبيت.
- [x] تدفق تسجيل الدخول بالبريد والتحقق منه واستعادة كلمة المرور موجود في الكود.\n- [ ] التسجيل/الدخول بالهاتف عبر SMS مضاف في الكود؛ يتطلب تفعيل Phone provider والنطاقات المسموحة في Firebase Console، ثم اختبار SMS حقيقي قبل اعتباره جاهزاً.
- [x] المحادثات الفردية والمجموعات والرسائل والمكالمات مبنية على Firebase وWebRTC.
- [x] بناء APK تجريبي عبر GitHub Actions.
- [ ] قواعد Firestore منشورة ومراجعة ومختبرة ضد الوصول غير المصرح به.
- [ ] إشعارات Android الأصلية عبر FCM مثبتة ومختبرة والتطبيق في الخلفية أو مغلق.
- [ ] اختبار عملي على جهازين وحسابين: تسجيل، بحث، رسائل، صور/صوت، حالات، مكالمات، وحالات انقطاع الشبكة.
- [ ] مراجعة التشفير واستعادة المفاتيح. النسخة الحالية تحفظ المفتاح الخاص محلياً، والمجموعات ليست مشفرة طرفاً لطرف.
- [ ] إعداد APK إصدار موقّع بمفتاح إصدار محفوظ خارج المستودع، والتحقق من إمكانية تحديث النسخة الموقعة.
- [ ] مراجعة إعدادات Firebase Auth المسموح بها، حدود الاستخدام، ومراقبة الأخطاء قبل فتح التسجيل للعامة.
- [ ] اختبار إمكانية الوصول، أحجام الشاشات، والأداء على أجهزة Android فعلية.

## فحوصات آلية موجودة في المستودع

يشغّل سير GitHub Actions مجموعة اختبارات Node.js لملف Service Worker قبل بناء APK. تغطي الاختبارات التي اجتازت التشغيل بالفعل:
- رفض رابط إشعار خارجي والحفاظ على وجهة داخل نطاق التطبيق.
- منع النقر على الإشعار من توجيه المستخدم إلى نطاق خارجي.
- عدم تخزين استجابات HTTP الفاشلة.
- عدم اعتراض طلبات غير GET مثل POST.

تُضاف اختبارات احتياط العمل دون اتصال للتحقق من الرجوع إلى صفحة التطبيق المخزنة عند التنقل، ومن عدم إرجاع HTML بدلاً من ملف ثابت مفقود؛ لا تُعدّ هذه الإضافات مؤكدة إلا بعد نجاح تشغيل CI الخاص بها. هذه الفحوصات لا تختبر قواعد Firebase أو تسليم الإشعارات من خادم أو عمل المكالمات على جهاز فعلي.

## مانع الإطلاق الأهم: قواعد Firestore

لا توجد حالياً نسخة قواعد Firestore في المستودع يمكن مراجعتها أو اختبارها. لا يجوز افتراض أن قاعدة البيانات آمنة. قبل الإطلاق:
1. احصل على قواعد المشروع المنشورة من Firebase Console أو Firebase CLI.
2. راجع كل مجموعة وعمليات القراءة والكتابة في التطبيق.
3. أضف القواعد إلى المستودع واختبرها باستخدام Firebase Emulator Suite واختبارات مستخدم مسجّل، ومستخدم غير عضو، ومستخدم غير مسجّل.
4. انشر القواعد بعد نجاح الاختبارات فقط، ثم اختبر التطبيق مرة أخرى.

لا تضع service-account JSON أو مفاتيح إدارية أو مفاتيح توقيع APK في المستودع أو في المحادثات.

## إشعارات Android

إشعارات Service Worker الحالية لا تكفي لإرسال تنبيه عندما تكون صفحة الويب أو التطبيق متوقفاً. يلزم دمج Firebase Cloud Messaging في مشروع Android، إعداد التطبيق في Firebase Console، توفير إعدادات Android المطلوبة بطريقة آمنة، ثم إرسال رسالة اختبار إلى جهاز فعلي وهو في الخلفية وبعد إغلاقه. لا تعتبر بناء APK ناجحاً دليلاً على نجاح الإشعارات.

## اختبار القبول قبل الإصدار

- [ ] حساب A وحساب B على جهازين منفصلين.
- [ ] رفض الوصول إلى المحادثة والرسائل والمكالمات والحالات من حساب ثالث غير عضو.
- [ ] اختبار الرسائل بعد إعادة تشغيل التطبيق، وتسجيل الخروج والدخول، وتحديث APK.
- [ ] التحقق من أن الرسائل الفردية لا تُقرأ من الخادم وأن رمز الأمان يتطابق على الطرفين.
- [ ] اختبار فشل الكاميرا والميكروفون، أذونات الإشعارات، الإنترنت الضعيف، وإعادة الاتصال.
- [ ] إنشاء نسخة إصدار موقعة، تثبيتها على جهاز نظيف، ثم اختبار التحديث فوق النسخة السابقة.
- [ ] الاحتفاظ بسجل نتائج الاختبار وتاريخ الإصدار ورقم البناء.

## معنى الجاهزية

نجاح GitHub Actions يعني أن البناء اكتمل فقط؛ لا يثبت سلامة قواعد Firebase أو نجاح الاتصال الحقيقي أو الإشعارات عند الإغلاق. إلى أن تُغلق الموانع الحرجة، توصف النسخة بأنها **نسخة تجريبية** وليست إصداراً عاماً جاهزاً.
